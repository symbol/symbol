# Creating Accounts from Private Keys

This tutorial shows how to create <accounts:> for the Symbol blockchain in two ways: generating a new random account
and creating an account from an existing private key.

## Code Explanation

### Creating a Random Account

{{ tutorial.code_snippet(['py:9:25', 'js:9:24']) }}

A random account is generated by creating a random <private key:>.
The private key is the secret that controls the account and must be kept secure.

The process involves three steps:

1. **Generate a random private key:** <dy:PrivateKey.random> creates a cryptographically secure random private key
    using the underlying cryptographic library.

    !!! warning "Store your private key securely"
        The private key gives full control over the account and any assets it holds.
        If you lose the private key, you lose access to the account permanently.
        If someone else obtains the private key, they can control the account.

        Never share your private key with anyone, and always store it in a secure location.

2. **Create a key pair:** The facade's <dy:KeyPair> constructor takes the private key and mathematically derives the
    corresponding <public key:>.
    While the private key must remain secret, the public key can be safely shared with anyone.

3. **Derive the address:** The network's address derivation method converts the public key into an <address:>,
    which is a shorter, human-readable, network-specific identifier for the account.

### Creating an Account from a Private Key

{{ tutorial.code_snippet(['py:28:46', 'js:27:44']) }}

If you already have a private key, you can recreate the account by loading it.

The process is similar to creating a random account, except the private key is provided directly instead of
being randomly generated.

The <dy:PrivateKey> constructor accepts the private key as either a hexadecimal string or raw bytes.
In this example, the private key is loaded from the `PRIVATE_KEY` environment variable as a hex string, with a
default value provided for demonstration purposes.

Once the key pair is created, the public key and address can be derived in the same way as with a random account.

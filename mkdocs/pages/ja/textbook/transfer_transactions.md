# 転送トランザクション

転送トランザクション
:   ある[アカウント](default:アカウント)から別のアカウントへ[モザイク](default:モザイク)や任意のメッセージを送信するための[トランザクション](default:トランザクション)。

転送トランザクションは Symbol で最も一般的なタイプであり、資産の移転や簡易な通信を可能にします。

## 主な特徴 {: #key-features }

* **モザイク転送**

    1 つまたは複数の[モザイク](default:モザイク)を転送トランザクションに添付できます。
    すべてのモザイクは 1 人の送信者から 1 人の受信者へ送られます。
    このため、転送トランザクションはシンプルで直接的な資産移転に最適です。

* **メッセージ機能**

    任意の平文または暗号化メッセージを含めることができます。
    モザイクを含める必要はないため、メッセージだけを送信することも可能です。
    これにより、資産転送に加えて簡単な通信も行えます。

* **アグリゲート対応**

    複数の転送トランザクションを 1 つの[アグリゲートトランザクション](default:アグリゲートトランザクション)にまとめることができます。
    これにより、1 件のトランザクションで複数の送信者および複数の受信者を扱うことが可能になります。

* **マルチシグ対応**

    転送トランザクションは他のトランザクションと同様に[マルチシグアカウント](default:マルチシグアカウント)に対応しています。
    これにより、複数のアカウントによる承認を要求でき、複雑なガバナンススキームを構築できます。

## 構造 {: #structure }

[共通トランザクション構造](./transactions.md#common-transaction-structure)に加えて、
転送トランザクションには以下の属性があります。

| 属性名                     | 説明                                                       |
| -------------------------- | ---------------------------------------------------------- |
| **受信者アドレス**         | 受信者を特定するアドレスまたはネームスペースのエイリアス。 |
| **転送するモザイクの一覧** | 転送対象の 0 個以上のモザイク。                            |
| **任意のメッセージ**       | 最大 1024 バイトの平文または暗号化メッセージ。             |

### 受信者アドレス {: #recipient-s-address }

受信者は[アドレス](default:アドレス)または[ネームスペース](default:ネームスペース)のエイリアスで指定できます。

!!! warning "所有していないアドレスへ送信した資産は失われます"
    チェーン上にまだ出現していないアドレス宛にモザイクを送信することが可能です。

    これは通常の動作としてサポートされていますが、
    受信者がその宛先アドレスを制御していることを十分に確認する必要があります。
    対応する[秘密鍵](default:秘密鍵)を誰も持っていない場合、送信されたモザイクは永久にロックされてしまいます。

### 転送するモザイクの一覧 {: #list-of-transferred-mosaics }

1 件の転送トランザクションには最大 **255 個のモザイク**を含めることができます。
この一覧を空にすることもでき、その場合は資産を伴わないメッセージのみを送信できます。

各エントリには、[モザイク ID](default:モザイク)（または[ネームスペース](default:ネームスペース)のエイリアス）と数量を指定します。
数量はそのモザイクの「絶対単位」で数える整数です。

モザイクの[可分性](default:可分性)プロパティは、モザイク作成時に設定され `0` から `6` の範囲を取り、
1 全体単位が何絶対単位に相当するかを定義します。
例えば、[XYM](default:XYM) の可分性は `6` であるため、`1'000'000` 絶対単位が 1 全体単位の XYM に相当します。
絶対単位と全体単位の換算方法について詳しくは、[モザイク](./mosaics.md#divisibility)ページを参照してください。

一覧に含まれるいずれかのモザイクを送信者が十分に保有していない場合、ネットワークはそのトランザクションを拒否します。

### 任意のメッセージ {: #optional-message }

トランザクションには最大 1024 バイトのメッセージを含めることができます。

Symbol プロトコルはメッセージのエンコーディング形式を標準化していません。
送信者と受信者がフォーマットやエンコーディング方式（例：UTF-8、JSON、HEX）を事前に合意する必要があります。
慣例的に、ほとんどのウォレットやアプリケーションは UTF-8 エンコーディングを使用します。

!!! note "暗号化の慣例"

    暗号化をサポートするため、Symbol 上のアプリケーションでは「最初の 1 バイト」で暗号化の有無を示す**慣例**が定められています。

    * 先頭バイトが `0x00` の場合、後続のバイトは暗号化されていないメッセージです。
    * 先頭バイトが `0x01` の場合、後続のバイトは受信者の公開鍵を用い、
      AES ブロック暗号（[CBC モード](https://ja.wikipedia.org/wiki/ブロック暗号モード#CBC)）で暗号化されたメッセージです。
      受信者のみが復号できます。

    この接頭バイトの分、メッセージの最大長は 1023 バイトになります。

    この慣例は [Symbol デスクトップウォレット](../userbook/desktop-wallet/install.md)、
    [Symbol Explorer](https://symbol.fyi) など多くのアプリケーションでサポートされていますが、
    Symbol プロトコルそのものの一部ではありません。
